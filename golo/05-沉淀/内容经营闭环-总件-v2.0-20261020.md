## 第一部分 · 认知：先把闭环说清楚

### 1.1 这个名字指什么

内容经营闭环，指的是**把内容当作一项经营要素来运转的循环机制**：它有明确的投入、可计量的产出、可留存的资产，并且最后一个工位必须回过头去改变第一个工位的输入。

它和"内容生产流程"的差别不在于步骤多少，而在于**方向**。生产线把内容当交付物，交付完即结束；闭环把内容当资本，结束之处正是下一轮的起点。

### 1.4 为什么分三层：三类动作、三类受众

三层按**目标—策略—执行**三类动作拆分，每层有明确的用户，避免所有信息堆在一起导致看不清。

| 层 | 动作类别 | 给谁看 | 屏上允许出现什么 | 绝不允许出现什么 |
|---|---|---|---|---|
| 一级 部门协同 | 目标 | CEO／运营总监／内容总监 | 六个核心节点、部门与部门之间怎么串、各部门 ROI、怎么复盘 | 任何执行细节 |
| 二级 关键判断 | 策略 | 达人／素材／运营／图片四部门主管 | 核心关注·交付·承接三行，定做什么产品、多少消耗、什么素材、预算怎么分 | 步骤与时长 |
| 三级 执行细节 | 执行 | 一线员工 | 步骤、负责人、验收人、时长、经验阈值、AI 工具卡 | 改写上级口径 |

**关键认知**：同一节点在一、二、三级本质是**同一业务环节**，只是受众和颗粒度不同。项目负责人要横向看全，但各角色是分级别看的、只取自己那层。

## 第二部分 · SOP、决策、提效

### 2.1 三块分别是什么

这是对外讲 AI 赋能的三大方向，口径以 10 月 20 日收稿为准。

| 方向 | 定义 | 交付形态 | 判据 |
|---|---|---|---|
| SOP | 梳理企业现有业务链路，明确哪些节点可被 AI 改造，作为赋能的**基础参照** | 一张分层的链路图 ＋ 每格的三行契约 | 换个人照做能否出同样结果；出错能否定位到某一格 |
| 决策 | 把部门主管沉淀在个人经验里的决策逻辑，转化为**公司可复用的公共资产**，降低对核心人员的依赖 | 保留／调整／停止清单、优先级与预算分配规则、可引用的模型与案例 | 能否说清"为什么选 A 不选 B、依据哪条记录"；核心人员不在场时这个判断还在不在 |
| 提效 | 针对**单点工作场景**落地 AI 工具（内容生成、自动投流、自动上架等），提升单点投入产出比 | 挂在具体节点上的工具卡：输入·提效重点·交付·人工负责·效果验证 | 同口径比较同类任务的成本与人效，且必须先有基线 |

**一句话记法**：SOP 是贯穿全链路、必须遵照执行的标准；决策只是这条标准链路里的一个环节；提效让整条 SOP 运转得更快。

三句话展开：

**SOP 贯穿全程。** 它不是六格中的某一格，而是从 01 到 06 整条链都要遵照执行的标准，也是三层分图能够成立的前提。没有 SOP，决策没有对象（不知道该改哪一格），提效没有落点（不知道交给哪一步）。

**决策嵌在其中一格，位置在 05 回到 02 的那条回流线上。** 它的实质内容是把主管个人经验里的判断变成公司公共资产——这是"降低对核心人员依赖"的唯一路径，也是企业核心能力所在的位置。它不凌驾于链路之上，而是在链路里指定位置发生。

**提效挂在执行动作上。** 它作用于三级各格的具体步骤（03 的出片出图、04 的上传建计划、06 的整理入库），价值是省时间省钱省返工。它不产生标准，也不做决策。

### 2.3 讲给新客户时要换说法

对内与已合作伙伴可沿用 2.1 的表述；面向新客户要转成更易懂的阐释——例如把 SOP 讲成"先帮你把旧链路梳理出来，一起找出哪些节点能交给 AI"，把决策讲成"把你们几个主管脑子里的判断搬到纸面上，变成谁都能调用的东西"，把提效讲成"某一个动作省多少人工，省下的能算出来"。

### 2.4 三种常见混法

**把提效当 SOP。** 先上工具再补链路，结果是给混乱加速：工具装得越多，返工越多。达人筛选把链路从 11 步压到 9 步，省掉的"合作预审"与"建联沟通"正是判断留痕的地方——SOP 未固化就先砍这两步，人是省了，数据断了。

**把决策下放给工具。** 花钱、下播、验收、定优先级这几类判断留在人手上（工具卡上"人工负责"那一栏就是为此而设）。把它们交给机器，等于把企业核心能力外包出去。

**把三层当成三份文档。** 三层是同一业务环节的三种颗粒度，不是三套并行体系。出现"一级里有执行时长、三级里改上级口径"，就是串层了。

## 第四部分 · 怎么推

### 4.1 顺序不能反

先接数据，再接会议，最后改指标。缺少单条可溯源之前，复盘只能吵感觉；复盘没有指名回流动作之前，报表只是挂在墙上的画。

| 步骤 | 做什么 | 完成标志（可检查） |
|---|---|---|
| 第一步 · 接血管 | 素材、投放、订单三侧数据以唯一编码强关联，做到双向可查 | 任取一条素材，能查出它的假设来源与实际效果数据 |
| 第二步 · 起心跳 | 周级复盘固定输入表与输出格式，结论必须指名改哪处输入 | 台账中出现"保留／调整／停止"、责任人与验证时间 |
| 第三步 · 通代谢 | 资源、模型、案例三类资产入库并设置调用条件 | 下一轮策略文档中能指出引用了哪条沉淀 |

### 4.2 SOP 从哪来、怎么把关

这套 SOP 不是沿用旧流程，而是通过访谈 4–5 位核心部门主管（重点人物沟通 3–4 次、一天跨 4–5 个部门）梳理得出，已覆盖全链路节点。把关四条：

**建及格线。** 自己先熟悉现有 SOP 核心逻辑，形成"及格线"认知框架，再对照对方表述核验；必要时要求现场操作演示。

**识别敷衍。** 旧流程常带过期时间节点。通过追问"是否在用"、多轮交流验证是否最新版本。

**课题分离。** 标准答案已交付；对方不重视、不去做，是对方的问题，不因此改口径也不因此背锅。

**不升级为结论。** 原图带问号的职责、未计数的数值、紫色卡片上的目标值，整理时一律保留原样并挂待确认。

### 4.3 落地推进

**借有拍板权的人调动相关人员，而非逐一面谈。** 以邵杰、任卓才的判断为最终标准——先拿出自己的初步方案，若被否决再按他们的方案执行。

**配套 SOP 由对应主管用约三天跑通完善**，补充每步记录什么数据、记录哪些表格维度等细节；这些细节属三级，不回填到一级屏上。

**演练在前，正式汇报在后。** 与邵杰、悟空先做认知颗粒度对齐演练；正式汇报对象是郭总。汇报前把一级六个节点讲顺，二、三级细节也要大致了解，避免被问到答不上来。

再带上三句关于赋能口径的话：

**一，SOP 贯穿全程**，它是整条链路都要遵照执行的标准，不是六格之一。

**二，决策是链路里的一个板块**，位置在复盘回到策略那一格；它的实质是把主管个人经验变成公司公共资产。

**三，提效只针对执行动作**，挂在具体节点上、要有基线才能验收，它让 SOP 转得更快，但不产生标准。

> 使用本件的边界：SOP 是承载物，不是成绩。指标写的是目标方向，不等于已实现收益；未实际计数的需求不写频次与占比；商家详情页的宣传主张与工具补充的场景推测，都不得记成已验证的用户事实。

## 附录 A · 向郭总模拟汇报话术（可直接照用）

以下为 10 月 20 日会话中模拟向郭总汇报"新款女健身衣内容经营闭环"的话术，原样整理。

郭总，我们现在整个内容的经营闭环，大概分为六个核心节点。

**第一个节点是内容业务目标。** 我们要打一个品，比如现在做一款新的女健身衣，那么会有相关的人——老板您、还有内容总监——围绕这个事拆解一个经营目标，把样品、卖点、怎么卖、大概要卖多少钱这些确定下来。

**第二个节点是内容策划。** 因为我们整个闭环是围绕内容去做的，有素材部、有达人部，他们需要短视频。这个节点会去定对应的方向：内容应该怎么做、短视频大概什么方向、怎么参考同行，这些是拆解，还没开始做。

**第三个节点是内容制作。** 拆解完之后，要开始真正做内容了，分为图片、视频，主要是三个部门：短视频部、图片部、达人部。

**第四个节点是内容运营。** 内容做完之后，会把图片和视频给到运营部。运营部拿这些视频去投放、跑 ROI、赛马，看哪些素材的投放 ROI 比较高、能带来比较高的 GMV，就重点关注这些素材，把它的预算拉高。

**第五个节点是策略复盘。** 跑了一批素材之后，达人部、短视频部、运营部开始复盘：哪些素材好、ROI 跑得好的视频回流到内容部，去迭代下一次的策略。

**第六个节点是资产沉淀。** 跑到这个节点，闭环差不多已经跑出一些比较好的 SOP 了，比如做短视频的 SOP、做图片做海报的 SOP。沉淀的这些 SOP 又能回流到第一个内容业务目标——下次我们做类似的新款时，会基于前面的积累去做迭代。就这样，整个闭环一次一次地迭代。

**汇报要点提醒**

- **紧扣"钱"**：重点围绕 GMV、投放 ROI、预算分配这些老板关心的点讲；把西鸣的流程套到高乐捷身上，不违和。
- **先讲六个节点闭环**：老板一看就懂，认同后再展开二级细节，有疑问再解释，不要一上来就堆细节。
- **核心逻辑就一句**：做出视频 → 投放 → 赛马 → 把跑得好的素材给更高预算。
- **汇报对象决定讲哪一层**：第一级抽象给老板，第二级给主管，第三级给执行员工。

## 附录 B · 闭环体检表（十二项四组，现场自查用）

填写规则：每项只写**是／否／部分**；凡填"是"，必须写出具体的表名、单据号或文档章节，写不出位置视同"否"。任何一组出现两个及以上"否"，该组对应的回流路径即视为断开。

| 接缝 | 检查项 | 结果 | 证据位置 |
|---|---|---|---|
| 看得见 | 每条素材有唯一标识，且标识在同一系统内不重复 | | |
| 看得见 | 由素材标识可查到它所属的款号与主打卖点 | | |
| 看得见 | 由素材标识可查到实际投放它的计划、消耗与成交结果 | | |
| 改得动 | 每次复盘的输入是固定的数据表，而非临时取数 | | |
| 改得动 | 复盘结论落成"保留／调整／停止"三类动作之一 | | |
| 改得动 | 结论写明改哪个输入、谁执行、什么时候回看 | | |
| 留得下 | 有可复用资源库（镜头、达人、模板），且标注使用条件 | | |
| 留得下 | 有内容模型记录：人群、卖点、场景、表达的组合与适用范围 | | |
| 留得下 | 有正反案例，保留效果数据与复盘结论，不只留成片 | | |
| 算得清 | 同一条链上同时看得到制作成本、投放消耗与成交 | | |
| 算得清 | 指标使用可比口径，未把相关性直接写成因果 | | |
| 算得清 | 目标值与实际值分栏记录，未实现的收益不写成成果 | | |

**结果怎么用**：十二项全"是"→ 环是通的，重点转向缩短单轮周期。第一组有"否"→ 先补数据关联，别先开复盘会。第二组有"否"→ 复盘在产出报告而不产出决策。第三组有"否"→ 每一轮都在重新交学费，入库不等于沉淀。第四组有"否"→ 闭环在纸面上存在、在账面上不存在。

> 本表只提供检查口径，不含目标值与承诺比例。阈值需按账号与品类试跑后商定，跨品牌、跨账号的经验数值不得直接沿用。

## 附录 C · 二级与三级节点明细（应对追问）

### 二级六节点：关注点与动作

| 节点 | 负责人 | 核心关注 | 动作／交付 | 承接 |
|---|---|---|---|---|
| 01 内容业务目标 | 内容项目负责人／内容总监 | 做什么产品、要多少消耗与素材 | 产品/样品＋消耗目标＋素材需求量 | 内容策略组据此研究与规划 |
| 02 内容策略 | 素材部＋达人部负责人 | 定内容策略方向 | 策略组做研究；编导＋剪辑拆爆款、提炼模板与关键变量。交付 人群×需求×场景＋内容方向＋模型 | 三路制作 |
| 03 内容制作 | 素材部／达人部／平面设计部 | 三路产出合格素材 | 短视频（编导·剪辑·拍摄·模特）；达人（商务 BD·星图编导）；平面（设计师出主图/SKU/详情页） | 发布与运营承接 |
| 04 内容运营 | 投手（一级作"运营负责人"，口径待统一） | 短视频／商品链接 ROI | 投视频＋投商品链接（原链路 vs AI 链路）；盯单条计划点击率/转化率、千次展现成本 | 数据回填复盘 |
| 05 内容策略复盘 | 素材部＋达人部负责人 | 策略优化方案 | 数据复盘（对照经营目标看差距）＋内容复盘（检验人群/卖点/场景/表达假设）＋策略调整（保留/调整/停止） | 方案→返回 02；经验案例→06 |
| 06 资产沉淀 | 各部门 | 方案·经营数据沉淀 | 资源沉淀、模型沉淀、案例沉淀 | 支撑下一轮制作／策略／决策 |

### 三级六节点：关注点与动作

| 节点 | 关注点 | 核心执行动作 | 负责人／验收 |
|---|---|---|---|
| 01 | 定总目标输入 | 明确项目负责人、产品/样品、消耗目标、素材需求量（只定盘，不执行） | 项目负责人 |
| 02 | 把策略拆成可执行研究动作 | 十步研究（两版顺序并存，见 3.3） | 策略组；编导＋混剪拆爆款 |
| 03 | 按方向产出合格素材 | 三路：短视频（脚本/分镜→拍摄或 AI→成片验收）；达人（筛选→脚本审核→发布交付）；平面（卖点→设计或 AI 生图→审核出图） | 编导·剪辑·拍摄·模特；商务 BD·星图编导；设计师 |
| 04 | 上架与投放承接 | 上架（接收合格图片→上架/替换→确认链路与图位）；投放（接收成片→上传→建计划→投放，原链路 vs AI 链路） | 运营／投手 |
| 05 | 用数据归因、反哺策略 | 数据复盘（视频表现窗口＋图片经营数据）＋内容复盘（检验假设）＋输出待验证结论回填 02 | 项目编导、项目运营 |
| 06 | 沉淀可复用资产 | 资源沉淀、优质内容模型沉淀、正反案例沉淀 | 各部门 |

**一句话记法**：二级问"这一步靠什么判断、交给谁、交什么"；三级问"具体分几步、谁做、谁验收、做多久"。
