> **口径说明（先读这一段）。** 本文分三层写，可信度不同，请勿混用：① **现状流程**来自运营口述 + 三张千川后台截图，属“访谈现状”，未逐条实操验证；② **千川侧机制与接口**来自巨量千川开放平台公开文档与第三方生产级实现复盘，接口路径与限制是真实的，但**必须以我方实际授权账号联调验证为准**；③ **改造方案**是 FDE 侧整理理解后的建议，凡有歧义或未定的地方一律标 ⚠️ 并归入第七节《待确认清单》，不做推断式补齐。

## 一、要解决的问题

内容库（`golovejoy.com.cn/apps/content/`）里存着素材本体和创作信息，千川里存着投放数据，两边**没有任何主键能对上**。现在唯一的关联手段是“文件名一致 + 人工复制搜索”，所以素材投得好坏回不到创作端，复盘只能靠人记。

一句话目标：**让内容库里的每一条视频，自带它在千川的身份证（material_id）和它的投放结果。**

### 2.1 千川侧真实发生了什么（把口述部分补成事实）

- **上传即得 ID。** 视频进千川视频库后由平台分配一个数字素材 ID（截图 3 中文件名下方那串），素材分析列表里同样按这串 ID 展示（截图 1）。这串 ID 就是天然的关联外键，人现在没有用它。
- **上传有硬性规格门槛。** 截图 2 明确：竖版 9:16、码率 ≥516kbps、大小 ≤1000M、分辨率 720×1280～1440×2560、时长 4s～300s。不合规直接传不上去，这是现状里“要下载再上传”的真实原因之一。
- **有 ID ≠ 有数据。** 素材只是躺在库里时没有消耗；只有被挂进投放计划并真实起量，素材分析里才会出现消耗与 ROI。所以“数据回流”的前提是**素材与计划的关系**，不是素材本身。
- **改名和打标签是现状唯一的对齐手段。** 截图 3 里文件名与标签都带编辑入口（红箭头所指），运营正是靠改这两处去匹配内容库名称。
- **审核与首发是独立状态。** 上传成功≠可投，还要过审；素材是否“首发”另有标记，会影响拿量。

## 三、现状的七个断点

| 编号 | 断点 | 表现 | 影响 |
|---|---|---|---|
| B1 | 系统之间无对接 | 内容库出片后，运营要下载再手工上传千川 | 重复搬运、版本易传错、时效差 |
| B2 | 关联靠字符串 | 靠文件名/标签一致来匹配，改名、加后缀即断链 | 无主键，历史数据无法批量对齐 |
| B3 | 数据不回内容库 | 内容库看不到消耗与 ROI，必须切到千川后台 | 复盘两张皮，无法按卖点/作者聚合 |
| B4 | 素材复用无归属 | 同一条素材被多计划、多账户复用 | 消耗算不清归谁，测品结论失真 |
| B5 | 当天数据会回刷 | 结算、退款、补贴类指标存在回刷 | 当天看到的 ROI 不是最终口径 |
| B6 | 编导看不到数据 | 编导侧无千川入口（访谈已确认） | “数据→内容”的反向优化断在源头 |
| B7 | 无投放动作留痕 | 谁在何时把哪条素材投到哪个计划，没有记录 | 出问题无法追责，也无法沉淀 SOP |

## 四、改造后流程（To-Be）

改造只做一件事：**把第 7—10 步从“人在两个后台之间搬运和对名字”，换成“系统用 material_id 双向记账”。**

| # | 环节 | 动作 | 关键点 |
|---|---|---|---|
| 1 | 编码 | 内容库视频 ID 重新编码：**款号_卖点_时间_作者_主题_版本**（六段，下划线分隔） | 编码是“人看的身份证”，不是数据库主键；规则见 4.1 |
| 2 | 自动上传 | 内容库集成自动投放，调千川开放平台上传视频，**文件名直接写编码名** | 上传前先按文件指纹去重，已存在则复用 material_id |
| 3 | 记账 | 内容库回写 material_id、审核状态、计划 ID、投放时间 | 建立 `账户 + 文件指纹 → material_id` 映射表 |
| 4 | 自动投放 | 由内容库发起建计划 / 给已有计划补素材 | ⚠️ 是否放开“系统自动花钱”需管理层拍板（见 QC-04） |
| 5 | 数据回流 | 定时拉素材维度报表，按 material_id 落到内容库 | 每小时刷当天、每日重刷 7 天、每周重刷 30 天 |
| 6 | 同屏复盘 | 内容库一条视频上同时看到：编码 + 消耗 + ROI + 点击率 + 计划 | 编导、运营、老板看同一张表 |

### 4.1 六段编码规则（QC-01 已锁定 · 2026-10-14 马亚鹏拍板）

格式：**款号_卖点_时间_作者_主题_版本**，段间统一用下划线 `_`。

示例：`JS07_00_261014_01_01_V01`（整串 24 字符）——读作"JS07 这款 · 卖点未梳理 · 2026-10-14 · 01 号作者 · 01 号主题 · 第一版"。

| 段 | 长度 | 取值范围 | 怎么生成 | 缺省与占位 |
|---|---|---|---|---|
| 款号 | 4 | 沿用商品「款式编码」原样（`JS07`、`YJ13`） | 上传素材时**必选关联款号**，下拉选择、不允许手输 | 未关联款号不允许入库 |
| 卖点 | 2 | `01`–`99` 数字码 | 22 款卖点重新梳理后按码表取值 | **未梳理一律 `00`** |
| 时间 | 6 | `YYMMDD` | 系统自动生成，人不填 | 取哪个时刻见 QC-15 |
| 作者 | 2 | `01`–`99` 短码 | 由「人 → 短码」码表映射；内容库另存钉钉 `userId` 作外键 | 改名、离职不影响历史编码 |
| 主题 | 2 | `01`–`99` 数字码 | 对应该视频是按哪段提示词 / 编导文案创作的，需先建主题码表 | 未定用 `00` |
| 版本 | 3 | `V01`–`V99` | 同前缀迭代时递增 | 首版 `V01` |

机器校验正则：`^(JS|YJ)[0-9]{2}_[0-9]{2}_[0-9]{6}_[0-9]{2}_[0-9]{2}_V[0-9]{2}$`

四条硬规矩（决定这套编码能不能被机器解析，务必写进录入校验）：

1. **段数固定 6、只用 `_` 分隔**，字段内部不得再出现 `_`、`-`、空格、中文与全角字符——千川侧文件名与搜索框都要吃这个规则。
2. **除款号外全部定长数字**，整串长度恒定 24 字符，可直接当文件名，也便于在 Excel / SQL 里按分隔符切成六列做聚合分析。
3. **编码只增不改**：素材一旦上传到千川，编码不得回改；要调整就升 `V02`。回改会让历史数据全部错位，正是现状断点 B2 的成因。
4. **编码不是主键**：数据库主键仍是内容库自有 ID + 千川 `material_id`，编码只承担"人一眼看得懂、搜索框输得进"。两者同时落库，即使将来编码规则再变，历史关联也不断。

这样做的三个直接收益：在千川搜索框输 `JS07` 就能拉出这款全部素材；按前缀排序天然把同款聚到一起；后期与商品上架打通时，款号段就是与聚水潭 / 商品主数据对表的现成外键。

需要落地的四张码表（内容库字典表，运营侧可维护，FDE 提供结构）：

| 码表 | 内容 | 现状 | 归口 |
|---|---|---|---|
| 款号表 | 全量在售 / 历史款号 | 有销售榜 22 款，但**不等于款号主数据**（见 QC-13） | 商品 / 运营 |
| 作者码表 | 人 → 2 位短码，另存钉钉 `userId` | 未建（见 QC-14） | 内容部 + 人事 |
| 主题码表 | 提示词 / 编导文案 → 2 位码 | 未建（见 QC-14） | 编导（刘凡、小天） |
| 卖点码表 | 每款卖点 → 2 位码 | 未梳理，暂全 `00` | 运营 + 编导 |

### 4.2 关联主键怎么选（这是整个改造的技术命门）

**结论：material_id 做外键，编码名做人看的展示名，两者都存，不靠名字匹配。**

理由：文件名是可变的（人随手一改）、跨账户不唯一、且千川侧同名素材本就允许存在；material_id 是平台分配、账户内唯一、不可变。历史遗留素材没有 material_id 记录，需要一次性回填（见 QC-03）。

## 五、技术版：要接哪些接口

下表接口路径来自巨量千川开放平台公开文档与第三方生产级实现复盘；**2026-10-14 已用官方接口的多语言 SDK 源码逐项复核路径与返回字段**（SDK 由公开文档生成，路径与文档一致）。这些接口在他方账户实测跑通，但我方账号能否调用取决于权限点开通情况，联调第一步就是逐项验权。

| 环节 | 接口（open_api） | 方法 | 关键参数 / 字段 | 用途 |
|---|---|---|---|---|
| 授权 | `/open_api/oauth2/access_token/`、`/open_api/oauth2/refresh_token/` | POST | `app_id`、`auth_code`、`secret`、`refresh_token` | 换/续 token；access_token 短有效期，须自动刷新重试 |
| 账户 | `/open_api/oauth2/advertiser/get/` | GET | — | 当前 token 可访问的授权账户 |
| 账户 | `/open_api/2/customer_center/advertiser/list/` | GET | `advertiser_id` | 工作台展开子账户（多千川账户场景必需） |
| 上传 | `/open_api/2/file/video/ad/` | POST | `advertiser_id`、视频文件/URL、`filename`、`signature` | 上传视频；**响应同步返回 `id`/`video_id`/`material_id`/`url`/`signature`/`filename`/`source`/`create_time`，不等审核** |
| 上传 | `/open_api/2/file/image/ad/` | POST | 同上 | 图片素材（本期可后置） |

### 5.1 标准调用顺序（不要乱接）

刷新 token → 展开子账户 → 拉账户汇总 → 拉计划列表 → 拉计划详情 → 拉计划商品 → **拉计划素材** → 查素材首发标记 → 需要更细维度时先查 `config/get` → 再按主题查 `data/get`。

素材维度报表要先在 `config/get` 里确认主题是否开放。已在他方样本中取数成功的素材/视频类主题包括 `ROI2_IMAGE_AGG_MATERIAL_ANALYSIS`、`SITE_PROMOTION_PRODUCT_POST_DATA_VIDEO`；另有若干主题**已开放但要求额外必填过滤条件**（如 `ecp_app_id`、`anchor_id`、`aggregate_smart_bid_type`）——这不是“官方不支持”，而是要先把业务过滤参数确定下来。

### 5.2 硬约束与坑（照抄他方实测结论，联调时逐条复验）

- **权限点**：广告主若未开通 `/open_api/2/file/video/ad/` 权限，上传任务直接失败——这是账户权限问题，不是架构问题。**授权链接若带错 scope，可能只授权到素材、拿不到投放账户。**
- **频控**：素材上传与查询必须节流；他方建议同账户上传并发 2、计划绑定并发 3～5，不要无限并发，否则易被限流。
- **异步与超时**：上传必须走后台任务，不能同步阻塞页面；接口偶发超时，读写与素材接口分别设 timeout + retry；token 过期时要能刷新后重试。
- **回刷**：结算、退款、补贴类指标会回刷，当天抓取不等于最终口径，必须定期重刷（每小时当天 / 每日 7 天 / 每周 30 天）。
- **不要依赖千川 PC 端页面内部接口**：那些接口虽可用，但不属于开放平台公开能力，无稳定性承诺，改版、字段调整、限流、风控都是高风险事件。
- **多账户**：高乐捷侧存在多个千川账户，必须先确定“哪个账户投的”才能定位 material_id（见 QC-02）。

### 5.3 建议的最小可行切片（两周内可验证）

不碰“自动投放”，先只做**只读打通**：① 授权 + 拉子账户；② 拉计划列表与计划下素材；③ 按 material_id 拉素材维度消耗/ROI；④ 用现有文件名做一次批量匹配，把能对上的素材回填 material_id；⑤ 内容库详情页显示消耗与 ROI。跑通即证明 B3、B6 被解决，再谈上传与自动投放。

### 5.4 复核结论一：material_id 是上传响应同步返回的，不等审核

原流程图把「返回 material_id」画在千川后台泳道，属**表述错误**，已修正。事实是：

- 调 `POST /open_api/2/file/video/ad/` 成功后，**响应体里直接给** `id`、`video_id`、`material_id`、`url`、`signature`、`filename`、`source`、`create_time`。也就是说素材 ID 与审核无关，上传成功即有、即可记账。
- 审核是素材的**后续状态**，公开能力里它更像**查询态**而不是**推送态**：调 `GET /open_api/v1.0/qianchuan/material/get/` 拿素材列表，官方 Java SDK 的响应模型确认带 `material_id`、`video_id`；第三方 Go SDK 的同一素材模型还列出 `audit_status`（`PASS` 审核通过 / `REJECT` 审核拒绝 / `IN_PROGRESS` 审核中）、`material_delivery_type`（素材投放状态）、`creative_ids`。**两个 SDK 对审核字段不一致，官方 Java SDK 里我没检索到 `audit_status`**——所以"轮询哪个字段拿审核状态"必须以官方文档 + 我方账号实测确认（挂 QC-10），不预设结论。
- 若走异步上传（批量/大文件），则改为按任务轮询：官方有「获取异步上传视频文件结果」与「Adv 轮询任务结果」两个接口，本质仍是**我们主动去问，不是平台主动来通知**。
- 想在正式投放前先知道行不行，可用预审链路：`POST /open_api/v3.0/security/open_material_audit/` 送审，再 `GET /open_api/v3.0/security/audit_results/` 按送审对象 ID 拉结果。
- 官方确有「千川全域计划变更消息」数据推送服务，但公开文档里它推的是**计划变更**，未见"素材审核完成"这一推送主题。

**工程含义**：内容库不需要等审核回调。落地做法是"上传即写 material_id + 状态=待审"，再用定时任务轮 `material/get` 刷 `audit_status`，把 `PASS` 作为"可投"的门槛位。⚠️ 新增待确认 **QC-10**：是否可申请到素材审核结果的订阅推送主题（若可申请，可把轮询降级为兜底）。

### 5.5 复核结论二：建计划确实有 API，但分两条链路，别接错

- **全域推广链路**：`POST /open_api/v1.0/qianchuan/uni_aweme/ad/create/`，返回 `ad_id`。⚠️ 官方 SDK 对该接口的注释写得很明确：**"当前仅支持「直播全域推广-控成本投放」链路"**。高乐捷是商品/短视频带货为主，若要走这条，必须先确认是否覆盖"推商品/短视频"全域，否则建出来的计划类型不对。
- **标准/专业推广链路**：`POST /open_api/v1.0/qianchuan/ad/create/`，并配套 `ad/update/`、`ad/update_status/`、`ad/update_bid/`、`ad/update_budget/`、`ad/roi_goal_update/`、`ad/schedule_*`、`ad/detail_get`、`ad/get`、`ad/reject_reason`（计划审核建议）等一整套，生命周期可全托管。
- **给已有计划加素材**：官方文档《添加乘方&全域投放计划下素材》对应 `uni_promotion/ad/material/add/`；第三方 SDK 目前只封装了 `material/get`、`material/delete`，**没有 add**，说明该接口较新，需按官方文档直连并实测。
- **前置授权**：官方另有《客户申请全域投放授权》文档——全域投放相关接口**需要客户侧申请授权**，不是建了应用就自动能调。⚠️ 新增待确认 **QC-11**：高乐捷千川账户的全域投放授权由谁发起、审批周期多久。

**结论**：「内容库集成自动投放」技术上成立，但**选哪条链路要先定**（QC-12：全域 vs 标准推广）。建议自动投放第一步走标准推广 `ad/create`（链路成熟、生命周期接口齐全），全域推广等授权与适用范围确认后再上。

## 六、白话版：给运营和老板看的三句话

1. **现在**：片子拍完进内容库，运营还要把文件下载下来、再手动传到千川，投完之后想看来板，得复制文件名去千川搜索框粘贴——两个后台来回跳，一天对不了几条。
2. **改造后**：内容库自己会把片子传到千川，并把千川给的回执号记在素材档案上；数据每天自动回来，打开内容库就能看到这条片子花了多少钱、ROI 多少。
3. **为什么值得做**：编导第一次能看到自己拍的片子表现如何，“哪个卖点有效”就不再靠感觉，复盘会可以直接对着同一张表开。

| 场景 | 现在怎么做 | 改造后怎么做 |
|---|---|---|
| 素材上到千川 | 运营下载文件、手动上传 | 内容库一键/自动上传 |
| 找到这条素材的数据 | 复制文件名去千川搜索 | 内容库点开即见 |
| 判断哪个卖点行 | 凭印象、问运营 | 按卖点聚合消耗与 ROI |
| 编导参与复盘 | 看不到数据，不参与 | 同屏看数，直接改脚本 |
| 数据口径 | 当天看到啥算啥 | 自动重刷，标注回刷窗口 |
